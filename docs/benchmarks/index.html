Why these KPIs

The numbers our users actually care about

RAM — the founding story

Compass exists because Cursor + Docker ate a 16GB MacBook. Footprint and growth are tracked like bugs: 8 MB for 2,000 semantic entries, and we publish the delta because bloat is a bug.

Search latency — retrieval must feel instant

RAG quality is worthless if retrieval feels slow. Sub-millisecond at 2,000 entries; the target is sub-10ms at 1,000,000. The index grows; the latency shouldn't.

Embedding latency — the Neural Engine promise

All bundled models must stay under 100 ms per embedding. Current: 3–15 ms.

On the bench

Next metrics, in the open

FIM completion latency (p50/p95)

The <100ms claim, measured with the real 4B on-device model: time-to-first-token, prompt tokens/sec, generation tokens/sec, RSS before/after load. The metrics struct already exists in the harness — the run needs the model download and the stable merge. This is the marquee number; we won't publish it until we've actually measured it.

Startup-to-ready · index time · standalone app RAM

Launch → window usable; first + incremental index of a 100k-LOC repo; Release-build idle footprint. All queued, all published the moment they're measured.

Benchmarks run on every release and on demand — see theBenchmark workflow.
